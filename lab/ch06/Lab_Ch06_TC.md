# 第 6 課｜管理者自動儀表板：Excel 檔案、資料庫與互動式分析

> 本實作由三個核心單元與一個延伸單元組成，情境為虛構咖啡連鎖「半島咖啡」（Peninsula Coffee，共六間門市）：你的角色為分析人員，為管理者建置檢視營運的互動式儀表板。單元一為資料理解與指標定義：以 Hermes 讀取銷售資料（含七張工作表的 Excel 工作簿），盤點資料品質問題，並定義儀表板的關鍵指標（KPI）。單元二為示範導覽與儀表板建置：先開啓課程提供的完整示範儀表板，再以 Hermes 生成你自己的儀表板程式並於本機瀏覽器檢視、迭代改良。單元三為資料庫化：將資料匯入 SQLite 資料庫、以 SQL 回答管理問題，並為儀表板加入 Excel／SQLite 雙來源切換，理解檔案與資料庫之差異。延伸單元（選讀）簡介 MCP 連接器（excel-mcp-server）及其擴充助手操作 Excel 之用途。

## 單元二：示範儀表板導覽與自建儀表板

### 2.1 概念：管理者儀表板與 Streamlit

管理者儀表板將關鍵指標集中於單一畫面，取代每次手工整併的靜態報表。靜態報表每次更新均需手工重做；儀表板由程式讀取資料檔繪製畫面——此處「自動」的含義是：程式每次啟動或重新整理時重新讀取資料檔，資料檔更新後，畫面即呈現最新數字，無需重新製作報表。

儀表板需以可於瀏覽器檢視的互動程式實作；本實作採用 Streamlit——一套以 Python 撰寫資料應用的開源框架：單一程式檔即可產生含篩選器、圖表與表格的網頁介面，於本機瀏覽器執行，毋須部署伺服器。單一程式檔之形式亦便於由助手生成與迭代修改。

- Streamlit 官方文件（元件與 API 參考）：官方入口 https://docs.streamlit.io
- 官方安裝指引：官方入口 https://docs.streamlit.io/get-started/installation
- Plotly 互動圖表：官方入口 https://plotly.com/python/

### 2.2 開啓示範儀表板

課程提供一份完整示範儀表板；先完整瀏覽一遍，再動手建置你自己的版本。

1. 開啓 Windows PowerShell（開始功能表搜尋 PowerShell；不需要管理員模式）
2. 貼上以下第一行並按 Enter；等候安裝完成，再貼第二行並按 Enter：

```powershell
& "$env:LOCALAPPDATA\hermes\bin\uv.exe" tool install streamlit --with openpyxl --with plotly
& "$HOME\.local\bin\streamlit.exe" run "$HOME\Documents\hermes-sandbox\lab-ch06\demo_dashboard.py"
```

**預期**：第一行顯示安裝過程，最後出現 `Installed 1 executable: streamlit`；第二行顯示 `Local URL: http://localhost:8501`，瀏覽器自動開啓示範儀表板。

- 瀏覽器未自動開啓時：手動開啓瀏覽器，於位址列輸入 `http://localhost:8501`
- 此 PowerShell 視窗須保持開啓——關閉視窗即停止儀表板；建議保留開啓，稍後與你的版本對照

3. 依下表逐頁籤瀏覽（側欄另有資料期間、門市、通路三個篩選器，可隨時調整）：

| 頁籤 | 觀察重點 |
|---|---|
| 總覽 | 月營收何時最高？2026 與 2025 同期相比增減多少？ |
| 門市 | 哪間門市達標率最低？新開的「路氹城門市」資料涵蓋幾個月？ |
| 商品 | 營收最高的類別與毛利率最高的類別是否相同？ |
| 時段 | 一天中最繁忙的時段？週末與平日有何差異？ |
| 會員 | 會員與非會員的營收佔比？哪個等級貢獻最多？ |
| 資料品質 | 六類問題各多少筆？清洗前後營收差多少？——對照你在單元一盤點的問題清單 |

4. 試著將側欄「資料來源」切換至 `SQLite`：程式會自動把 Excel 資料庫化後再讀取。此切換機制為單元三之主題。

## 單元三：資料庫化與雙來源切換

### 3.1 概念：檔案與資料庫

Excel 檔案適合小規模、單人使用的資料分析；資料庫以結構化查詢語言（SQL）存取資料，適合多資料表關聯、多人並用與權限管理——零售企業的營運系統多以資料庫儲存交易資料，分析時再匯出為檔案。以 SQL 查詢資料庫，可直接取得彙總與跨資料表關聯的結果，無須先在試算表中整理資料。本單元將你的 Excel 資料「資料庫化」：匯入 SQLite（Python 內建的輕量資料庫引擎，毋須額外安裝），以 SQL 回答管理問題；再讓儀表板支援雙來源切換——同一畫面、不同資料來源，體會「資料層與呈現層分離」：資料存哪裡（Excel 或資料庫）與畫面怎麼呈現，是兩個可以分開的決定。

- SQLite 官方網站（SQL 語法與文件）：官方入口 https://sqlite.org
- Python sqlite3 模組官方文件：官方入口 https://docs.python.org/3/library/sqlite3.html
- SQL 教學（W3Schools）：https://www.w3schools.com/sql/


2. 記錄匯入方式：檔案型（Excel）與資料庫型（SQLite）的差異在哪裡？答案將用於小組討論。

## 延伸單元（選讀）：MCP 連接器簡介——excel-mcp-server

MCP（Model Context Protocol）為助手調用外部工具的標準協議。excel-mcp-server 為開源 MCP 伺服器：設定後，助手即可直接讀寫 Excel 檔案——讀取與更新儲存格、建立樞紐分析表、圖表與格式設定，且不需要安裝 Microsoft Excel。

日後於課程或工作中需要助手直接操作 Excel 檔案時，可依專案說明配置使用：

- 專案與工具清單：官方入口 https://github.com/haris-musa/excel-mcp-server

## 常見問題

| 症狀 | 處理 |
|---|---|
| 助手回覆無法讀取 xlsx（顯示 ModuleNotFoundError: openpyxl） | 回覆助手：`請安裝缺少的套件後重試`；或改用 2.2／2.4 節之 PowerShell 方式啟動（安裝指令已含 openpyxl 與 plotly） |
| 助手生成程式時顯示缺少 plotly | 回覆助手：`請安裝缺少的套件後重試`；PowerShell 安裝指令已含 `--with plotly` |
| 助手啟動儀表板後長時間沒有回覆 | 長時執行指令屬正常——直接於瀏覽器開啓對應網址；仍無畫面則改用 2.2／2.4 節之 PowerShell 方式 |
| PowerShell 出現 `streamlit` 相關錯誤且無法啟動 | 重新執行 2.2 節第一行安裝指令（重複執行會以最新設定重新安裝），完成後再執行啟動指令 |
| 瀏覽器顯示「無法連線」 | 確認對應的 PowerShell 視窗仍保持開啓；確認開啓的埠號與啟動訊息顯示的 `Local URL` 一致 |
| 瀏覽器未自動開啓 | 手動於瀏覽器位址列輸入對應網址（示範 8501／自建 8502） |
| 埠被占用無法啟動 | 於指令末尾加上 ` --server.port 8503`（或任一未被占用之埠），並以該埠開啓 |
| 修改 `dashboard.py` 後畫面未更新 | 於瀏覽器畫面點選 Rerun／Always rerun；或重新整理分頁 |
| 示範儀表板如何關閉 | 於其 PowerShell 視窗按 Ctrl+C；或直接關閉該視窗（建議保留開啓以便對照） |
| 雙來源切換後畫面報錯（3.4） | 將錯誤訊息貼回對話請助手排查；或請助手重新生成切換邏輯 |
| `sales.db` 建置失敗（提示檔案鎖定） | 關閉其他可能開著 `sales.db` 的程式與瀏覽器分頁，重試；或請助手改存新檔名後重跑 |
| 助手找到的品質問題不完整 | 使用 1.3 節之追問方式逐項確認；助手若把正常資料判為問題，追問其判斷理由 |
| `:free` 模型回應慢或顯示 429 | 免費層限速屬正常——稍候重試，或更換其他 `:free` 模型 |
