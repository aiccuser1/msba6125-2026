# 第 6 課｜管理者自動儀表板：Excel 檔案、資料庫與互動式分析

> 本實作由三個核心單元與一個延伸單元組成，情境為虛構咖啡連鎖「半島咖啡」（Peninsula Coffee，共六間門市）：你的角色為分析人員，為管理者建置檢視營運的互動式儀表板。單元一為資料理解與指標定義：以 Hermes 讀取銷售資料（含七張工作表的 Excel 工作簿），盤點資料品質問題，並定義儀表板的關鍵指標（KPI）。單元二為示範導覽與儀表板建置：先開啓課程提供的完整示範儀表板，再以 Hermes 生成你自己的儀表板程式並於本機瀏覽器檢視、迭代改良，最後以 Excel 樞紐分析完成人工核對。單元三為資料庫化與雙來源核對：將資料匯入 SQLite 資料庫、以 SQL 回答管理問題，並為儀表板加入 Excel／SQLite 雙來源切換，完成「樞紐分析—SQL—儀表板」三方核對。延伸單元（選做，建議在家完成）為以 MCP 連接器（excel-mcp-server）擴充助手直接操作 Excel 的能力。每個單元結束均有檢查清單，以供核對完成度。

## 學習目標（Learning Objectives）

完成本實作後，你將具備：

- 以 AI 助手讀取多工作表（七表）Excel 資料，說明其欄位結構、規模、時間範圍與資料品質問題

- 將資料匯入 SQLite 資料庫，以 SQL 回答管理問題
- 為儀表板加入 Excel／SQLite 雙來源切換，完成三方核對（樞紐分析—SQL—儀表板）
- （延伸）以 MCP 連接器擴充助手對 Excel 檔案之操作能力

### 1.2 資料理解：請助手讀取資料

資料分析的第一步是確認資料的欄位、規模與品質——資料理解先於指標定義與圖表設計。

1. 開啓 Hermes Desktop；在對話框輸入以下文字並送出（路徑中 `<你的用戶名>` 換成你的 Windows 用戶名）：

```
請讀取 C:\Users\<你的用戶名>\Documents\hermes-sandbox\lab-ch06\sales_2026.xlsx，回報：
一、各工作表的名稱與用途
二、每張工作表的欄位、資料列數與時間範圍
三、你觀察到的資料品質問題（缺值、重複、極端值、命名不一致等，逐項列出）
請只讀取，不要修改或清理檔案。
```

**預期**：助手回報七張工作表——`stores`（門市主檔）、`products`（商品主檔）、`customers`（會員主檔）、`promotions`（促銷行事曆）、`orders`（交易明細，為分析主體）、`returns`（退貨紀錄）、`targets`（門市月度目標），並列出 orders 的欄位（訂單編號、日期、時間、門市、通路、會員編號、商品、數量、單價、折扣、營收、成本、付款方式等）、規模（近兩萬列，19,967 列）與時間範圍（2025-01-01 至 2026-09-30）。

2. 若助手未提及任何品質問題，追問：

```
請再逐項檢查並回報結果：訂單列是否完全無重複、門市名稱是否完全一致、數量與單價是否有不合理數值、必填欄位是否有空白、訂單中的商品編號是否都存在於商品主檔、付款方式等欄位值是否有隱藏空白或格式不一致。
```

**預期**：助手逐項回答檢查結果。將發現的品質問題抄錄下來——本資料集共埋有六類問題（有些助手會全部找到，有些只找到一部分——這正是後續要核對的原因）。

### 1.3 追問：不放過任何疑點

助手第一輪回報通常不完整。選擇你懷疑的項目繼續追問，例如：

```
你說門市名稱一致——請列出 orders 工作表出現過的所有門市名稱，以及各自的列數。
```

**預期**：發現 `北區店` 與 `北區門市` 並存（主檔名稱為「北區門市」）。以同樣方式追問其他項目，直到六類問題都盤點完整或取得明確的檢查結果。

### 1.4 資料處理規則（本課共同基準）

資料品質問題必須先決定「如何處理」，各項核對才能進行。若樞紐分析、SQL 與儀表板各用不同口徑，數字永遠對不上。本課統一規則如下——**之後所有核對（樞紐分析、SQL、儀表板）一律以此為準**：

1. 移除完全重複列（保留第一列）
2. 排除數量極端列（`qty` 大於或等於 100）
3. 門市名稱正規化：`北區店` 統一為 `北區門市`
4. 付款方式欄位值去除前後空白
5. 訂單中不在商品主檔之商品（孤兒商品）保留並標記，但不列入商品與類別排名
6. 空白成本（`unit_cost`）不補值；毛利率僅計有成本之資料列

### 1.5 指標定義：與助手共同設計儀表板

管理儀表板呈現什麼，取決於管理者要回答什麼問題。指標定義先於圖表設計。

1. 在同一對話輸入：

```

一、營收類：總營收、淨營收（扣除退貨退款）、訂單數、平均客單價
二、月度營收趨勢與去年同期比較（2025 與 2026）
三、熱銷商品與類別營收、類別毛利率
四、各門市營收與月度目標達成率（對照 targets 工作表）
五、下單時段分布與通路（門店／網店／外送）分布
六、會員分析（等級營收佔比、消費前 10 名會員）與退貨率（對照 returns 工作表）

最後補充一至兩個你認為值得加入的指標，並說明理由。
```

2. 閱讀回覆後，記錄 KPI 清單。可請助手將清單整理為表格：`請把上述指標整理成表格：指標、計算方式、圖表類型、管理意義。`

**預期**：產出一份 KPI 清單，每項含計算方式與管理意義。

## 單元二：示範儀表板導覽與自建儀表板

### 2.1 概念：管理者儀表板與 Streamlit

管理者儀表板將關鍵指標集中於單一畫面，取代每次手工整併的靜態報表。靜態報表每次更新均需手工重做；儀表板由程式讀取資料檔繪製畫面——此處「自動」的含義是：程式每次啟動或重新整理時重新讀取資料檔，資料檔更新後，畫面即呈現最新數字，無需重新製作報表。

儀表板需以可於瀏覽器檢視的互動程式實作；本實作採用 Streamlit——一套以 Python 撰寫資料應用的開源框架：單一程式檔即可產生含篩選器、圖表與表格的網頁介面，於本機瀏覽器執行，毋須部署伺服器。單一程式檔之形式亦便於由助手生成與迭代修改。

- Streamlit 官方文件（元件與 API 參考）：官方入口 https://docs.streamlit.io
- 官方安裝指引：官方入口 https://docs.streamlit.io/get-started/installation
- Plotly 互動圖表（本課圖表套件）：官方入口 https://plotly.com/python/

### 2.2 開啓示範儀表板（本課最終成品）

課程提供一份完整示範儀表板——這是本課最終成品的樣貌。先在瀏覽器完整瀏覽一遍，再動手建置你自己的版本。

1. 開啓 Windows PowerShell（開始功能表搜尋 PowerShell；不需要管理員模式）
2. 貼上以下第一行並按 Enter；等候安裝完成，再貼第二行並按 Enter：

```powershell
& "$env:LOCALAPPDATA\hermes\bin\uv.exe" tool install streamlit --with openpyxl --with plotly
& "$HOME\.local\bin\streamlit.exe" run "$HOME\Documents\hermes-sandbox\lab-ch06\demo_dashboard.py"
```

**預期**：第一行顯示安裝過程，最後出現 `Installed 1 executable: streamlit`；第二行顯示 `Local URL: http://localhost:8501`，瀏覽器自動開啓示範儀表板。

- 瀏覽器未自動開啓時：手動開啓瀏覽器，於位址列輸入 `http://localhost:8501`
- 此 PowerShell 視窗須保持開啓——關閉視窗即停止儀表板；建議保留開啓，稍後與你的版本對照

3. 依下表逐頁籤瀏覽（側欄另有資料期間、門市、通路三個篩選器，可隨時調整）：

| 頁籤 | 觀察重點 |
|---|---|
| 總覽 | 月營收何時最高？2026 與 2025 同期相比增減多少？ |
| 門市 | 哪間門市達標率最低？新開的「路氹城門市」資料涵蓋幾個月？ |
| 商品 | 營收最高的類別與毛利率最高的類別是否相同？ |
| 時段 | 一天中最繁忙的時段？週末與平日有何差異？ |
| 會員 | 會員與非會員的營收佔比？哪個等級貢獻最多？ |
| 資料品質 | 六類問題各多少筆？清洗前後營收差多少？——對照你在單元一盤點的問題清單 |

4. 試著將側欄「資料來源」切換至 `SQLite`：程式會自動把 Excel 資料庫化後再讀取，兩邊數字完全相同。這正是單元三你要自己動手完成的事。

### 2.3 生成自建儀表板程式

在同一對話輸入（延續單元一之對話；`<你的用戶名>` 換成你的用戶名）：

```
請用 Python 與 Streamlit 撰寫儀表板程式，存為 C:\Users\<你的用戶名>\Documents\hermes-sandbox\lab-ch06\dashboard.py，需求：
一、讀取同資料夾的 sales_2026.xlsx（以 orders 為主，輔以 products、customers、promotions、returns、targets）
二、依下列資料處理規則先行清理：
  (1) 移除完全重複列；(2) 排除 qty >= 100 之列；(3) 門市名稱「北區店」統一為「北區門市」；
  (4) 付款方式去除前後空白；(5) 不在商品主檔之孤兒商品保留並標記、不列入商品與類別排名；
  (6) 空白成本不補值，毛利率僅計有成本之列
三、上方顯示六項指標：淨營收（扣除退貨退款）、訂單數、客單價、毛利率、退貨率、目標達成率
四、分頁或區塊呈現：月度營收趨勢（含 2025 與 2026 同期比較）、門市營收與目標達成、熱銷商品前 10 與類別營收、下單時段分布、通路分布、會員等級營收佔比與消費前 10 名會員
五、側欄提供資料期間、門市、通路篩選器
六、圖表使用 Plotly 套件
完成後回報：程式檔案路徑、讀取的資料欄位、以及你對資料的處理決定。
若執行環境缺少套件（如 pandas、openpyxl、plotly），請先安裝後繼續。
```

**預期**：助手回報已建立 `dashboard.py`。於檔案總管開啓 `lab-ch06` 資料夾，可見 `dashboard.py`、`demo_dashboard.py` 與 `sales_2026.xlsx` 三個檔案。

### 2.6 人工核對：Excel 樞紐分析

AI 產出的數字須人工抽查核實。以 Excel 樞紐分析獨立計算同一指標，與儀表板對照。**注意：原始資料含品質問題，須先依 1.4 規則清理工作區，再對照——此步驟正是「同一基準」原則的實踐。**

1. 以 Excel 開啓 `sales_2026.xlsx`，於下方工作表標籤 `orders` 上按右鍵 →「移動或複製」
2. 於對話框「目的活頁簿」選「（新活頁簿）」、勾選「建立複本」→ 按確定——新活頁簿即為你的清理工作區（不動原始檔）
3. 在新活頁簿執行三項清理：
   - 點選資料區任一格 → 功能區「資料」→「移除重複」→ 於對話框直接按確定（全欄位比對）
   - 功能區「資料」→「篩選」→ `qty` 欄下拉 → 數字篩選 → 大於或等於 → 輸入 `100` → 確定 → 選取篩選出的列 → 右鍵 → 刪除列 → 再取消篩選
   - 按 Ctrl+H（尋找與取代）→ 尋找 `北區店`、取代為 `北區門市` → 全部取代
4. 核對清理結果：資料列數應為 **19,951**（自 19,967 列移除 15 重複列與 1 極端列）
5. 點選資料區任一格 → 功能區「插入」→「樞紐分析表」→ 按確定 → 將 `store` 拖至「列」、`revenue` 拖至「值」（確認顯示「加總」）
6. 得到各門市營收後，與儀表板「門市」頁籤的門市營收並排比較
7. 核對基準（標準答案；若你的數字不符，先檢查 3 的三項清理是否完成）：

| 項目 | 數值（MOP） |
|---|---|
| 清洗後訂單數 | 19,951 |
| 清洗後營收合計 | 11,136,265.52 |
| 退款總額（returns 工作表） | 201,281.94 |
| 淨營收（扣退貨） | 10,934,983.58 |

**預期**：樞紐數字與儀表板一致。若助手在程式中對資料做了不同處理（如未排除極端值），可能出現差異——記錄差異，並回到對話追問助手原因。

## 單元三：資料庫化與雙來源核對

### 3.1 概念：檔案與資料庫

Excel 檔案適合小規模、單人使用的資料分析；資料庫以結構化查詢語言（SQL）存取資料，適合多資料表關聯、多人並用與權限管理——零售企業的營運系統多以資料庫儲存交易資料，分析時再匯出為檔案。本單元將你的 Excel 資料「資料庫化」：匯入 SQLite（Python 內建的輕量資料庫引擎，毋須額外安裝），以 SQL 回答管理問題；再讓儀表板支援雙來源切換——同一畫面、相同數字，體會「資料層與呈現層分離」：資料存哪裡（Excel 或資料庫）與畫面怎麼呈現，是兩個可以分開的決定。

- SQLite 官方網站（SQL 語法與文件）：官方入口 https://sqlite.org
- Python sqlite3 模組官方文件：官方入口 https://docs.python.org/3/library/sqlite3.html
- SQL 教學（W3Schools）：https://www.w3schools.com/sql/

## 延伸單元（選做——建議在家完成）：MCP 連接器——excel-mcp-server

### 4.1 概念

MCP（Model Context Protocol）為助手調用外部工具的標準協議。excel-mcp-server 為開源 MCP 伺服器，讓助手以工具形式讀寫 Excel 檔案——讀取儲存格、建立樞紐分析、圖表與格式設定；不需要安裝 Microsoft Excel。

- 專案與工具清單：官方入口 https://github.com/haris-musa/excel-mcp-server

### 4.2 配置

1. 於檔案總管位址列貼上 `%LOCALAPPDATA%\hermes` 後按 Enter；右鍵 `config.yaml` → 開啓方式 → 記事本
2. 按 Ctrl+F 搜索 `mcp_servers`：
   - 已存在：將以下內容新增於該區段之下，縮進層級與既有項目相同
   - 不存在：移至檔案最末尾，另起一行貼入整段（`mcp_servers:` 由第一列開始，不可有空格）
   - 將 `<你的用戶名>` 換成你的用戶名：

```yaml
mcp_servers:
  excel-mcp:
    command: "C:/Users/<你的用戶名>/AppData/Local/hermes/bin/uv.exe"
    args: ["tool", "run", "excel-mcp-server", "stdio"]
```

   縮進規定：`excel-mcp:` 前 2 個空格，`command:` 與 `args:` 前 4 個空格。路徑中的斜線使用 `/`（不是 `\`）。

3. 記事本選「文件 → 保存」，關閉記事本
4. 回到 Hermes 對話，輸入 `/reload-mcp` 並送出
5. 為避免改動原始資料：在檔案總管複製 `sales_2026.xlsx` 為 `sales_2026_mcp.xlsx`（點選檔案按 Ctrl+C，再按 Ctrl+V；對產生的複本按 F2 改名）
6. 驗證——輸入（`<你的用戶名>` 換成你的用戶名）：

```
請用 excel-mcp 工具讀取 C:\Users\<你的用戶名>\Documents\hermes-sandbox\lab-ch06\sales_2026_mcp.xlsx，回報 orders 工作表的欄位名稱與列數。
```

**預期**：助手調用名稱以 `mcp_` 開頭的工具完成讀取，回報欄位名稱與 19,967 列。首次調用時自動下載伺服器套件，需等候片刻。

7. 進階（可選）：請助手以 MCP 工具在複本上新增樞紐分析表：

```
請用 excel-mcp 工具在 sales_2026_mcp.xlsx 新增一張樞紐分析表工作表：以 store 為列標籤、revenue 加總為值。
```

**預期**：複本檔案出現新工作表；以 Excel 開啓複本檢視結果。
