# 第 7 課｜網絡診斷：以 AI 助手解讀互聯網連線與無線技術

> 本實作以你的電腦為對象，由本機逐層檢視至互聯網之連線。單元一盤點本機網絡設定——IP 位址、子網路遮罩、預設閘道、DNS 伺服器等項目及其作用。單元二執行名稱解析與連通測試——以域名查詢、ping 與路徑追蹤，檢視名稱如何轉為位址、資料如何逐跳傳遞。單元三檢視無線連線，並產出一份連線報告網頁——由助手生成報告，以本機網頁伺服器於瀏覽器檢視，理解客戶端與伺服器之分工。延伸單元（選讀）為半島咖啡擬定互聯網通信與行銷方案建議。全部診斷指令皆為唯讀，不變更你的系統設定。

## 學習目標（Learning Objectives）

完成本實作後，你將具備：

- 說明本機網絡設定各項元素（IPv4 位址、子網路遮罩、預設閘道、實體位址、DNS 伺服器）之作用
- 以 AI 助手執行網絡診斷指令（`nslookup`、`ping`、`tracert`、`netsh wlan`），並解讀其輸出
- 說明域名系統（DNS）如何將網域名稱解析為 IP 位址
- 檢視 Wi-Fi 連線參數，並對應無線標準（802.11）與帶寬概念
- 以本機網頁伺服器檢視報告，說明客戶端／伺服器架構與萬維網之運作
- 產出一份互聯網連線報告網頁
- （延伸）比較互聯網通信服務並提出方案建議

## 單元一：本機網絡設定盤點與解讀

### 1.1 建立工作資料夾

1. 開啓檔案總管（工作列上的資料夾圖示，或按鍵盤 Windows 鍵＋E）
2. 於上方位址列貼上 `C:\Users\<你的用戶名>\Documents\hermes-sandbox` 後按 Enter
3. 於資料夾空白處按右鍵 → 新增 → 資料夾；輸入名稱 `lab-ch07` 後按 Enter 確認

**預期**：`hermes-sandbox` 內新增 `lab-ch07` 資料夾。

### 1.2 檢視本機網絡設定

1. 開啓 Hermes Desktop；在對話框輸入以下文字並送出：

```
請在 PowerShell 執行 ipconfig /all，並以表格回報下列項目：
一、使用中的網絡介面（無線或有線）之名稱
二、IPv4 位址、子網路遮罩、預設閘道
三、實體位址（MAC）
四、DNS 伺服器位址
五、DHCP 伺服器位址
六、本機的 IPv6 位址（如有）
請貼出你實際執行的指令與原始輸出的關鍵行。
```

**預期**：助手回報使用中的介面；無線介面通常名為 WLAN（無線區域網路適配器），有線介面為乙太網路。IPv4 位址通常形如 `192.168.x.x` 或 `10.x.x.x`；預設閘道通常形如 `192.168.x.1`；DNS 伺服器為路由器或所屬網絡之位址；實體位址為 12 位十六進位（如 `A4-5E-60-…`）；IPv6 位址多以 `fe80::` 開頭。

2. 將回報結果抄錄為下表——單元三之報告將使用此表：

| 項目 | 你的數值 |
|---|---|
| 介面類型 | 無線／有線 |
| IPv4 位址 | |
| 子網路遮罩 | |
| 預設閘道 | |
| DNS 伺服器 | |
| 實體位址（MAC） | |

### 1.3 解讀：各項設定的意義

- **IPv4 位址**：裝置於網絡中的位址。`192.168.x.x`、`10.x.x.x` 等屬私人位址，僅於你的本地網絡內有效；各地網絡重複使用同一批號段而不衝突，對外則共用網絡的公開位址（第 4 節）。私人位址經路由器轉換後，對外代表你的網絡。
- **子網路遮罩**：界定本機與哪些位址同屬一個本地網絡
- **預設閘道**：本地網絡的出口——即路由器；目的地不在本地網絡的資料，一律先送往閘道轉送（第 1 節）。
- **實體位址（MAC）**：網絡介面卡的硬體位址，出廠固定；IP 位址可更換，MAC 不變
- **DNS 伺服器**：負責將網域名稱解析為 IP 位址之伺服器（第 4 節；單元二實際觀察）
- **DHCP 伺服器**：自動向本機指派 IP 位址、子網路遮罩、預設閘道與 DNS 伺服器等設定之服務；多由路由器兼任

- [ ] 六項數值抄錄完成

## 單元二：名稱解析、往返延遲與路徑追蹤

### 2.1 概念：封包交換與 DNS

互聯網以**封包交換**（packet switching）傳送資料：訊息切分為多個封包，各封包載有目的地資訊、可獨立經不同路徑前進，抵達後重組——沿途由路由器逐跳轉送（第 2 節）。因此存取網站並非沿單一路徑直達，而是由多個路由器逐跳（hop）轉送資料。名稱（如 `www.um.edu.mo`）須先經**域名系統**（DNS）解析為 IP 位址，資料方能尋址（第 4 節）。本單元依序檢視三個環節：名稱解析（`nslookup`）、往返延遲（`ping`）、逐跳路徑（`tracert`）。

### 2.2 名稱解析：nslookup

1. 在同一對話輸入：

```
請在 PowerShell 執行 nslookup www.um.edu.mo，回報：
一、你使用的 DNS 伺服器位址（與 1.2 抄錄的是否相同）
二、www.um.edu.mo 解析出的 IP 位址（可能多於一個）
三、以本次查詢為例，說明域名由右至左的層級（頂級域名、下層域名、主機名稱）
```

**預期**：回報 DNS 伺服器位址（`伺服器`或`Server`一行）與一至多個 IP 位址。以此例說明層級：`.mo` 為頂級域名（國家代碼）；`edu.mo`、`um.edu.mo` 逐層指定機構；`www` 為該主機名稱。解析結果是澳門大學網站的公開位址——與單元一你抄錄的私人位址屬不同層級。

2. （選做）再輸入以下文字，觀察解析失敗之症狀：

```
請再執行 nslookup www.um-no-such-domain.invalid，回報結果並說明與上一查詢之差異。
```

**預期**：助手回報域名不存在（找不到）。DNS 查詢失敗時，名稱無法轉為位址——瀏覽器即顯示「找不到網站」。

### 2.3 往返延遲：ping

1. 在同一對話輸入（以 1.2 抄錄之閘道位址取代「<閘道位址>」）：

```
請依序執行以下三個測試（各 4 次），以一表回報每一測試的成功或逾時、平均往返時間（ms）與封包遺失率：
一、ping <閘道位址>
二、ping www.um.edu.mo
三、ping 8.8.8.8
請貼出實際執行的指令。
```

**預期**：閘道往返時間通常小於 1 毫秒（同一本地網絡）；網站名稱測試數毫秒至數十毫秒；`8.8.8.8`（Google 公共 DNS 服務之位址）數十至兩百餘毫秒。三者遞增——反映距離與途經路由器之總數。

2. 將結果抄錄成表：

| 測試 | 成功／逾時 | 平均往返時間（ms） | 遺失率 |
|---|---|---|---|
| ping 閘道 | | | |
| ping www.um.edu.mo | | | |
| ping 8.8.8.8 | | | |

3. 判讀規則——出現異常時依此定位：

- 閘道不通：本地網絡問題；檢查 Wi-Fi 或線路。
- 閘道通、名稱不通、純位址（8.8.8.8）通：DNS 解析問題
- 純位址亦不通：對外連線受限或目標阻擋 ping 探測（見常見問題）

### 2.4 路徑追蹤：tracert

1. 在同一對話輸入：

```
請在 PowerShell 執行 tracert -h 15 -w 1000 www.um.edu.mo，回報：
一、總跳數，以及每一跳的位址與平均延遲
二、哪些跳顯示 *（逾時）
三、再以 www.google.com 為目標執行一次，比較兩者的跳數與延遲差異
```

**預期**：每一跳即途經的一個路由器。存取澳門大學網站路徑較短、延遲低；存取國際網站跳數較多（通常 8 至 15 跳）、延遲較高（常逾百毫秒）。部分跳顯示 `*` 屬正常——部分路由器不回應探測封包。

2. 解讀：路徑上的每一跳即第 2 節所述之逐跳轉送機制；同一目標兩次執行之路徑亦可能不同——封包交換網絡依當時流量狀況選擇可用路徑。將兩次追蹤之跳數與總延遲摘要抄錄備用。

### 2.5 單元二檢查清單

- [ ] `nslookup` 完成，DNS 伺服器與解析位址記錄完成
- [ ] 三項 `ping` 測試完成並填入對照表

## 單元三：無線接入與報告網頁

### 3.1 概念：Wi-Fi 與 802.11

無線網絡以無線電信號為傳輸介質（第 3 節）。Wi-Fi 依 IEEE 802.11 標準家族運作——較新世代（Wi-Fi 5／6，即 802.11ac／ax）提供更高傳輸速率（第 7 節）。**帶寬**（bandwidth）為通信介質的傳輸容量，單位為 Mbps、Gbps（第 3 節）。Wi-Fi 畫面顯示的「速率」為裝置與基地台議定的協商上限；實際體驗速率受共享、距離與干擾影響。

### 3.2 檢視 Wi-Fi 連線

1. 在同一對話輸入：

```
請在 PowerShell 執行 netsh wlan show interfaces，並回報：
一、介面名稱與狀態
二、SSID（網絡名稱）
三、無線電類型（radio type，如 802.11ac 或 802.11ax）
四、通道（channel）與訊號強度（百分比）
五、接收速率與傳輸速率（Mbps）
並以第 7 章概念說明無線電類型所對應的 Wi-Fi 世代。
```

**預期**：無線電類型對應 802.11 標準世代（802.11ax 為 Wi-Fi 6；802.11ac 為 Wi-Fi 5）；速率以 Mbps 計——對照帶寬概念（第 3 節）。使用有線連線或虛擬機之電腦若無 Wi-Fi 介面，見常見問題。

2. （課後選做）於不同位置重新執行本指令，記錄訊號強度與速率之變化。

### 3.3 生成報告網頁

1. 在同一對話輸入（`<你的用戶名>` 換成你的用戶名）：

```
請根據本對話中剛才實際測得的結果，生成一份網頁報告，存為 C:\Users\<你的用戶名>\Documents\hermes-sandbox\lab-ch07\network_report.html，內容包含：
一、標題「我的互聯網連線報告」
二、本機網絡設定表（1.2 之六項）
三、DNS 解析結果與三項 ping 測試結果表
四、tracert 兩個目標之跳數與延遲摘要
五、Wi-Fi 無線電類型、訊號強度與速率
六、以第 7 章概念為各部分寫一段簡短解讀（以中文撰寫）
網頁須為單一 HTML 檔，樣式簡潔。
```

**預期**：助手建立 `network_report.html`。於檔案總管雙擊可先以檔案形式預覽；核對數字與先前實測是否一致，有出入請助手修正。

### 3.4 以本機伺服器檢視報告

概念：瀏覽器（客戶端）向網頁伺服器（伺服器端）發出請求，伺服器回傳網頁——此即客戶端／伺服器架構（第 2 節）與萬維網之運作方式（第 6 節）。以下在**你的電腦內** 啟動一個網頁伺服器，再以瀏覽器檢視報告。`localhost` 指你這一台電腦本身——請求由本機瀏覽器送到本機伺服器，來回不經互聯網。

1. 開啓 Windows PowerShell（開始功能表搜尋 PowerShell；不需要管理員模式）
2. 貼上以下指令並按 Enter：

```powershell
& "$env:LOCALAPPDATA\hermes\bin\uv.exe" run --no-project python -m http.server 8000 --directory "$HOME\Documents\hermes-sandbox\lab-ch07"
```

**預期**：顯示 `Serving HTTP on 0.0.0.0 port 8000` 等訊息。首次執行可能需先下載 Python，稍候數十秒。此 PowerShell 視窗須保持開啓——關閉視窗即停止伺服器。

3. 開啓瀏覽器，於位址列輸入 `http://localhost:8000/network_report.html`，檢視報告。
4. （替代方式）由助手啟動——在同一對話輸入：

```
請在 C:\Users\<你的用戶名>\Documents\hermes-sandbox\lab-ch07 目錄啟動本機網頁伺服器（連接埠 8000），供應 network_report.html，完成後回報檢視網址。
```

**預期**：助手回報檢視網址；若助手持續執行而沒有回覆，直接於瀏覽器開啓 `http://localhost:8000/network_report.html`。

5. 檢視完成後關閉伺服器：於 PowerShell 視窗按 Ctrl+C；若由助手啟動，輸入 `請停止剛才的網頁伺服器`。

### 3.5 （選做）跨裝置檢視與無線技術

1. 由手機檢視報告：於手機瀏覽器開啓 `http://<你的 IPv4 位址>:8000/network_report.html`；手機須與電腦連上同一 Wi-Fi。此為以無線區域網絡存取本地伺服器之實例（第 3 節網絡類型；第 7 節無線接入）。
   - Windows 防火牆提示時，於「私人網路」勾選允許；此設定僅本步驟需要。
   - 若無法連線：部分公共網絡隔離用戶端（AP isolation）；此步驟為選做，不影響課堂完成。
2. 檢視藍牙裝置（第 7 節藍牙 PAN）。在同一對話輸入：

```
請在 PowerShell 執行 Get-PnpDevice -Class Bluetooth | Select-Object Status, FriendlyName | Format-Table -AutoSize，回報清單，並說明藍牙屬何種網絡類型。
```

**預期**：列出藍牙介面與裝置；藍牙構成個人區域網絡（PAN，802.15）。

3. （課後選做）檢視手機的無線技術：於手機設定查看行動網絡類型（5G／LTE，第 7 節蜂窩系統）、Wi-Fi 詳細資料（頻段與標準）與藍牙清單，記錄對照。

## 延伸單元（選讀）：互聯網通信與行銷方案建議

## 小組討論題

1. 你的 IPv4 位址是私人位址（`192.168.x.x` 等）——為何同一批號段在世界各地重複出現而不衝突？對外網站看到的又是哪一個位址？該位址由誰提供？
2. ping 閘道不足 1 毫秒，ping 國際網站逾百毫秒——請以封包交換、傳輸介質與地理距離說明差異（第 2、3 節）。
3. 若學校的 DNS 伺服器故障，可能出現哪些症狀？為何直接輸入 IP 位址仍能連上？企業可如何降低此風險？
4. Wi-Fi 協商速率動輒數百 Mbps，實際下載常僅數十 Mbps——列出至少三項原因（第 3 節帶寬；第 7 節無線）。

## 常見問題

| 症狀 | 處理 |
|---|---|
| ping 全部顯示「要求逾時」 | 先以 1.2 抄錄之閘道位址確認本地網絡；閘道可達而對外全逾時，可能為網絡或目標阻擋 ping 探測——改測 `8.8.8.8`；仍逾時則與鄰座結果對照後繼續（課堂網絡限制） |
| tracert 中多跳顯示 `*` | 正常——部分路由器不回應探測；重點為路徑整體與延遲趨勢 |
| `netsh wlan show interfaces` 回報無介面或服務未執行 | 桌上型電腦、乙太網路或虛擬機可能無 Wi-Fi——改以有線完成單元一二，3.2 以概念對照同學結果，或與鄰座對照 |
| 助手回覆籠統、未實際執行指令 | 追問：`請實際執行並貼出原始輸出。`（同一對話繼續） |
| 助手輸出中文亂碼 | 屬終端機編碼顯示問題；位址、毫秒、百分比等數字仍可判讀 |
| 本機伺服器無法啟動（`python` 不存在） | 使用 3.4 之 PowerShell 指令（首次自動下載 Python）；或改由助手啟動（3.4 第 4 點） |
| 連接埠 8000 被占用 | 改用 8080 等其他埠，並以該埠開啓網址 |
| 報告網頁中文顯示亂碼 | 請助手於 HTML 的 `<head>` 加入 `<meta charset="utf-8">` |
| 網頁報告數字與實測不符 | 將正確數字貼回對話，請助手更新（同一對話） |
| 手機無法開啓報告（3.5） | 確認為同一 Wi-Fi；防火牆允許「私人網路」；部分網絡隔離用戶端——屬正常，選做步驟可略 |
| Windows 防火牆提示 | 啟動伺服器或跨裝置檢視時出現；於「私人網路」勾選允許；其他情況取消即可 |
| `:free` 模型回應慢或顯示 429 | 免費層限速屬正常——稍候重試，或更換其他 `:free` 模型 |
