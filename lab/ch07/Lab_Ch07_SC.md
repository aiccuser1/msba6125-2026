# 第 7 课｜网络诊断：以 AI 助手解读互联网连线与无线技术

> 本实作以你的电脑为对象，由本机逐层检视至互联网之连线。单元一盘点本机网络设定——IP 位址、子网路遮罩、预设闸道、DNS 伺服器等项目及其作用。单元二执行名称解析与连通测试——以域名查询、ping 与路径追踪，检视名称如何转为位址、资料如何逐跳传递。单元三检视无线连线，并产出一份连线报告网页——由助手生成报告，以本机网页伺服器于浏览器检视，理解客户端与伺服器之分工。延伸单元（选读）为半岛咖啡拟定互联网通信与行销方案建议。全部诊断指令皆为唯读，不变更你的系统设定。

## 学习目标（Learning Objectives）

完成本实作后，你将具备：

- 说明本机网络设定各项元素（IPv4 位址、子网路遮罩、预设闸道、实体位址、DNS 伺服器）之作用
- 以 AI 助手执行网络诊断指令（`nslookup`、`ping`、`tracert`、`netsh wlan`），并解读其输出
- 说明域名系统（DNS）如何将网域名称解析为 IP 位址
- 检视 Wi-Fi 连线参数，并对应无线标准（802.11）与带宽概念
- 以本机网页伺服器检视报告，说明客户端／伺服器架构与万维网之运作
- 产出一份互联网连线报告网页
- （延伸）比较互联网通信服务并提出方案建议

## 单元一：本机网络设定盘点与解读

### 1.1 建立工作资料夹

1. 开启档案总管（工作列上的资料夹图示，或按键盘 Windows 键＋E）
2. 于上方位址列贴上 `C:\Users\<你的用户名>\Documents\hermes-sandbox` 后按 Enter
3. 于资料夹空白处按右键 → 新增 → 资料夹；输入名称 `lab-ch07` 后按 Enter 确认

**预期**：`hermes-sandbox` 内新增 `lab-ch07` 资料夹。

### 1.2 检视本机网络设定

1. 开启 Hermes Desktop；在对话框输入以下文字并送出：

```
请在 PowerShell 执行 ipconfig /all，并以表格回报下列项目：
一、使用中的网络介面（无线或有线）之名称
二、IPv4 位址、子网路遮罩、预设闸道
三、实体位址（MAC）
四、DNS 伺服器位址
五、DHCP 伺服器位址
六、本机的 IPv6 位址（如有）
请贴出你实际执行的指令与原始输出的关键行。
```

**预期**：助手回报使用中的介面；无线介面通常名为 WLAN（无线区域网路适配器），有线介面为乙太网路。IPv4 位址通常形如 `192.168.x.x` 或 `10.x.x.x`；预设闸道通常形如 `192.168.x.1`；DNS 伺服器为路由器或所属网络之位址；实体位址为 12 位十六进位（如 `A4-5E-60-…`）；IPv6 位址多以 `fe80::` 开头。

2. 将回报结果抄录为下表——单元三之报告将使用此表：

| 项目 | 你的数值 |
|---|---|
| 介面类型 | 无线／有线 |
| IPv4 位址 | |
| 子网路遮罩 | |
| 预设闸道 | |
| DNS 伺服器 | |
| 实体位址（MAC） | |

### 1.3 解读：各项设定的意义

- **IPv4 位址**：装置于网络中的位址。`192.168.x.x`、`10.x.x.x` 等属私人位址，仅于你的本地网络内有效；各地网络重复使用同一批号段而不冲突，对外则共用网络的公开位址（第 4 节）。私人位址经路由器转换后，对外代表你的网络。
- **子网路遮罩**：界定本机与哪些位址同属一个本地网络
- **预设闸道**：本地网络的出口——即路由器；目的地不在本地网络的资料，一律先送往闸道转送（第 1 节）。
- **实体位址（MAC）**：网络介面卡的硬体位址，出厂固定；IP 位址可更换，MAC 不变
- **DNS 伺服器**：负责将网域名称解析为 IP 位址之伺服器（第 4 节；单元二实际观察）
- **DHCP 伺服器**：自动向本机指派 IP 位址、子网路遮罩、预设闸道与 DNS 伺服器等设定之服务；多由路由器兼任

- [ ] 六项数值抄录完成

## 单元二：名称解析、往返延迟与路径追踪

### 2.1 概念：封包交换与 DNS

互联网以**封包交换**（packet switching）传送资料：讯息切分为多个封包，各封包载有目的地资讯、可独立经不同路径前进，抵达后重组——沿途由路由器逐跳转送（第 2 节）。因此存取网站并非沿单一路径直达，而是由多个路由器逐跳（hop）转送资料。名称（如 `www.um.edu.mo`）须先经**域名系统**（DNS）解析为 IP 位址，资料方能寻址（第 4 节）。本单元依序检视三个环节：名称解析（`nslookup`）、往返延迟（`ping`）、逐跳路径（`tracert`）。

### 2.2 名称解析：nslookup

1. 在同一对话输入：

```
请在 PowerShell 执行 nslookup www.um.edu.mo，回报：
一、你使用的 DNS 伺服器位址（与 1.2 抄录的是否相同）
二、www.um.edu.mo 解析出的 IP 位址（可能多于一个）
三、以本次查询为例，说明域名由右至左的层级（顶级域名、下层域名、主机名称）
```

**预期**：回报 DNS 伺服器位址（`伺服器`或`Server`一行）与一至多个 IP 位址。以此例说明层级：`.mo` 为顶级域名（国家代码）；`edu.mo`、`um.edu.mo` 逐层指定机构；`www` 为该主机名称。解析结果是澳门大学网站的公开位址——与单元一你抄录的私人位址属不同层级。

2. （选做）再输入以下文字，观察解析失败之症状：

```
请再执行 nslookup www.um-no-such-domain.invalid，回报结果并说明与上一查询之差异。
```

**预期**：助手回报域名不存在（找不到）。DNS 查询失败时，名称无法转为位址——浏览器即显示「找不到网站」。

### 2.3 往返延迟：ping

1. 在同一对话输入（以 1.2 抄录之闸道位址取代「<闸道位址>」）：

```
请依序执行以下三个测试（各 4 次），以一表回报每一测试的成功或逾时、平均往返时间（ms）与封包遗失率：
一、ping <闸道位址>
二、ping www.um.edu.mo
三、ping 8.8.8.8
请贴出实际执行的指令。
```

**预期**：闸道往返时间通常小于 1 毫秒（同一本地网络）；网站名称测试数毫秒至数十毫秒；`8.8.8.8`（Google 公共 DNS 服务之位址）数十至两百余毫秒。三者递增——反映距离与途经路由器之总数。

2. 将结果抄录成表：

| 测试 | 成功／逾时 | 平均往返时间（ms） | 遗失率 |
|---|---|---|---|
| ping 闸道 | | | |
| ping www.um.edu.mo | | | |
| ping 8.8.8.8 | | | |

3. 判读规则——出现异常时依此定位：

- 闸道不通：本地网络问题；检查 Wi-Fi 或线路。
- 闸道通、名称不通、纯位址（8.8.8.8）通：DNS 解析问题
- 纯位址亦不通：对外连线受限或目标阻挡 ping 探测（见常见问题）

### 2.4 路径追踪：tracert

1. 在同一对话输入：

```
请在 PowerShell 执行 tracert -h 15 -w 1000 www.um.edu.mo，回报：
一、总跳数，以及每一跳的位址与平均延迟
二、哪些跳显示 *（逾时）
三、再以 www.google.com 为目标执行一次，比较两者的跳数与延迟差异
```

**预期**：每一跳即途经的一个路由器。存取澳门大学网站路径较短、延迟低；存取国际网站跳数较多（通常 8 至 15 跳）、延迟较高（常逾百毫秒）。部分跳显示 `*` 属正常——部分路由器不回应探测封包。

2. 解读：路径上的每一跳即第 2 节所述之逐跳转送机制；同一目标两次执行之路径亦可能不同——封包交换网络依当时流量状况选择可用路径。将两次追踪之跳数与总延迟摘要抄录备用。

### 2.5 单元二检查清单

- [ ] `nslookup` 完成，DNS 伺服器与解析位址记录完成
- [ ] 三项 `ping` 测试完成并填入对照表

## 单元三：无线接入与报告网页

### 3.1 概念：Wi-Fi 与 802.11

无线网络以无线电信号为传输介质（第 3 节）。Wi-Fi 依 IEEE 802.11 标准家族运作——较新世代（Wi-Fi 5／6，即 802.11ac／ax）提供更高传输速率（第 7 节）。**带宽**（bandwidth）为通信介质的传输容量，单位为 Mbps、Gbps（第 3 节）。Wi-Fi 画面显示的「速率」为装置与基地台议定的协商上限；实际体验速率受共享、距离与干扰影响。

### 3.2 检视 Wi-Fi 连线

1. 在同一对话输入：

```
请在 PowerShell 执行 netsh wlan show interfaces，并回报：
一、介面名称与状态
二、SSID（网络名称）
三、无线电类型（radio type，如 802.11ac 或 802.11ax）
四、通道（channel）与讯号强度（百分比）
五、接收速率与传输速率（Mbps）
并以第 7 章概念说明无线电类型所对应的 Wi-Fi 世代。
```

**预期**：无线电类型对应 802.11 标准世代（802.11ax 为 Wi-Fi 6；802.11ac 为 Wi-Fi 5）；速率以 Mbps 计——对照带宽概念（第 3 节）。使用有线连线或虚拟机之电脑若无 Wi-Fi 介面，见常见问题。

2. （课后选做）于不同位置重新执行本指令，记录讯号强度与速率之变化。

### 3.3 生成报告网页

1. 在同一对话输入（`<你的用户名>` 换成你的用户名）：

```
请根据本对话中刚才实际测得的结果，生成一份网页报告，存为 C:\Users\<你的用户名>\Documents\hermes-sandbox\lab-ch07\network_report.html，内容包含：
一、标题「我的互联网连线报告」
二、本机网络设定表（1.2 之六项）
三、DNS 解析结果与三项 ping 测试结果表
四、tracert 两个目标之跳数与延迟摘要
五、Wi-Fi 无线电类型、讯号强度与速率
六、以第 7 章概念为各部分写一段简短解读（以中文撰写）
网页须为单一 HTML 档，样式简洁。
```

**预期**：助手建立 `network_report.html`。于档案总管双击可先以档案形式预览；核对数字与先前实测是否一致，有出入请助手修正。

### 3.4 以本机伺服器检视报告

概念：浏览器（客户端）向网页伺服器（伺服器端）发出请求，伺服器回传网页——此即客户端／伺服器架构（第 2 节）与万维网之运作方式（第 6 节）。以下在**你的电脑内** 启动一个网页伺服器，再以浏览器检视报告。`localhost` 指你这一台电脑本身——请求由本机浏览器送到本机伺服器，来回不经互联网。

1. 开启 Windows PowerShell（开始功能表搜寻 PowerShell；不需要管理员模式）
2. 贴上以下指令并按 Enter：

```powershell
& "$env:LOCALAPPDATA\hermes\bin\uv.exe" run --no-project python -m http.server 8000 --directory "$HOME\Documents\hermes-sandbox\lab-ch07"
```

**预期**：显示 `Serving HTTP on 0.0.0.0 port 8000` 等讯息。首次执行可能需先下载 Python，稍候数十秒。此 PowerShell 视窗须保持开启——关闭视窗即停止伺服器。

3. 开启浏览器，于位址列输入 `http://localhost:8000/network_report.html`，检视报告。
4. （替代方式）由助手启动——在同一对话输入：

```
请在 C:\Users\<你的用户名>\Documents\hermes-sandbox\lab-ch07 目录启动本机网页伺服器（连接埠 8000），供应 network_report.html，完成后回报检视网址。
```

**预期**：助手回报检视网址；若助手持续执行而没有回复，直接于浏览器开启 `http://localhost:8000/network_report.html`。

5. 检视完成后关闭伺服器：于 PowerShell 视窗按 Ctrl+C；若由助手启动，输入 `请停止刚才的网页伺服器`。

## 延伸单元（选读）：互联网通信与行销方案建议

情境：半岛咖啡（六间门市、员工约 40 人）拟检视其互联网通信与行销方案。以助手完成下列两项任务：

```
你是半岛咖啡的资讯顾问。公司有六间门市与约 40 名员工，需要即时通讯、视讯会议、档案共享，并让外勤人员安全存取门市系统。请以「互联网服务与业务应用」的概念（电子邮件与即时通信、IP 语音、整合通信、虚拟专用网），提出一份方案对照表：服务类型、建议用途、成本考量、注意事项，并以三句总结建议。
```

2. 对外行销。在同一对话输入：

```
承上，公司网站希望于搜寻引擎获得曝光。请说明搜寻引擎行销（SEM）的基本做法（关键字广告与自然排序之别），并为「澳门咖啡豆」等三个关键字建议投放重点与衡量方式。
```

**预期**：产出两份简短建议（表格加结论）。本单元供讨论，不纳入课堂评核。

## 小组讨论题

1. 你的 IPv4 位址是私人位址（`192.168.x.x` 等）——为何同一批号段在世界各地重复出现而不冲突？对外网站看到的又是哪一个位址？该位址由谁提供？
2. ping 闸道不足 1 毫秒，ping 国际网站逾百毫秒——请以封包交换、传输介质与地理距离说明差异（第 2、3 节）。
3. 若学校的 DNS 伺服器故障，可能出现哪些症状？为何直接输入 IP 位址仍能连上？企业可如何降低此风险？
4. Wi-Fi 协商速率动辄数百 Mbps，实际下载常仅数十 Mbps——列出至少三项原因（第 3 节带宽；第 7 节无线）。

## 常见问题

| 症状 | 处理 |
|---|---|
| ping 全部显示「要求逾时」 | 先以 1.2 抄录之闸道位址确认本地网络；闸道可达而对外全逾时，可能为网络或目标阻挡 ping 探测——改测 `8.8.8.8`；仍逾时则与邻座结果对照后继续（课堂网络限制） |
| tracert 中多跳显示 `*` | 正常——部分路由器不回应探测；重点为路径整体与延迟趋势 |
| `netsh wlan show interfaces` 回报无介面或服务未执行 | 桌上型电脑、乙太网路或虚拟机可能无 Wi-Fi——改以有线完成单元一二，3.2 以概念对照同学结果，或与邻座对照 |
| 助手回复笼统、未实际执行指令 | 追问：`请实际执行并贴出原始输出。`（同一对话继续） |
| 助手输出中文乱码 | 属终端机编码显示问题；位址、毫秒、百分比等数字仍可判读 |
| 本机伺服器无法启动（`python` 不存在） | 使用 3.4 之 PowerShell 指令（首次自动下载 Python）；或改由助手启动（3.4 第 4 点） |
| 连接埠 8000 被占用 | 改用 8080 等其他埠，并以该埠开启网址 |
| 报告网页中文显示乱码 | 请助手于 HTML 的 `<head>` 加入 `<meta charset="utf-8">` |
| 网页报告数字与实测不符 | 将正确数字贴回对话，请助手更新（同一对话） |
| 手机无法开启报告（3.5） | 确认为同一 Wi-Fi；防火墙允许「私人网路」；部分网络隔离用户端——属正常，选做步骤可略 |
| Windows 防火墙提示 | 启动伺服器或跨装置检视时出现；于「私人网路」勾选允许；其他情况取消即可 |
| `:free` 模型回应慢或显示 429 | 免费层限速属正常——稍候重试，或更换其他 `:free` 模型 |
